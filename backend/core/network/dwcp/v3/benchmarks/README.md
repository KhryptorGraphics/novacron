# QUARANTINED - do not re-enable without a real rewrite

Every `*_test.go` file in this directory was renamed to `*_test.go.disabled`
(novacron-38p session work) after two independent findings:

1. **novacron-v4y** (earlier this session): none of these files import the
   `dwcp` package - verified via grep, zero matches. Every "benchmark" here
   is a closed-form formula over hardcoded scenario tables. It benchmarks
   the test's own arithmetic, not the DWCP implementation. Numbers like
   "38568 GB/s zero-copy throughput" measure nothing real.

2. **novacron-38p** (this session): `backend/core/network/dwcp/v3/BENCHMARK_RESULTS.md`
   - a document reporting "All Phase 0 targets EXCEEDED" with numbers
   including 3,489 GB/s single-stream TCP baseline and 1,807,251 GB/s
   (>1.8 exabytes/sec) zero-copy transfer at 16MB, both physically
   impossible for real network I/O - is almost certainly generated by this
   same package. The AMST section is even internally self-contradictory:
   it claims "PASS - Far exceeded" a >70% bandwidth-improvement target
   while its own table shows 8 streams (2,519 GB/s) performing WORSE than
   1 stream (3,489 GB/s baseline).

Real, verified replacements exist elsewhere in this session's work:
- `backend/core/network/dwcp/v3/tests/benchmark_hde_compression_test.go` -
  real `HDE.CompressMemory` at all three tiers.
- `backend/core/network/dwcp/v3/tests/benchmark_migration_wan_bandwidth_test.go` -
  real compress + real bandwidth-throttled AMST.Transfer + real decompress,
  at assumed-but-documented WAN bandwidth profiles.
- `backend/core/network/dwcp/migration_adapter_benchmark_test.go` - real
  end-to-end `MigrationAdapter.MigrateVMMemory`/`MigrateVMDisk`.

If this package is ever revived, it needs to actually call into `dwcp`
(and be checked against reality the way the files above were), not be
un-suffixed back to `.go` as-is.
